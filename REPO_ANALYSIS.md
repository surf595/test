# Разбор репозитория pdm_bot (по доступному локальному срезу)

## Ограничения доступа
- Прямой `git clone` удалённого репозитория в текущем окружении не прошёл из‑за сетевого ограничения (HTTP 403).
- Поэтому разбор ниже основан на коде, который доступен в текущем рабочем каталоге `/workspace/test` и, судя по структуре, соответствует проекту с ботом и веб-интерфейсом.

## Что это за проект
Репозиторий выглядит как комбинация двух частей:
1. **Python Telegram-бот `pdm_bot`** с Retrieval-Augmented Generation (RAG):
   - хранение пользовательских настроек и истории в SQLite,
   - индексация локальной библиотеки документов (`txt/md/pdf/docx`) в Qdrant,
   - генерация ответов через OpenAI Chat + embeddings,
   - команды для администрирования и управления индексом.
2. **Статический веб-интерфейс** (`index.html`, `app.js`, `styles.css`) для онлайн-консультаций и групповой работы (управление местами в круге участников).

## Архитектура Python-части

### Точка входа и запуск
- `pdm_bot/app/main.py`:
  - инициализирует логирование, проверяет конфиг,
  - поднимает БД,
  - проверяет/создаёт коллекцию Qdrant,
  - запускает worker индексации,
  - делает стартовую синхронизацию библиотеки,
  - регистрирует Telegram-обработчики и запускает polling.

### Конфигурация
- `pdm_bot/app/config.py`:
  - берёт ключи и параметры из `.env` (Telegram/OpenAI/Qdrant/параметры чанкинга/лимиты),
  - создаёт директорию `docs`,
  - валидирует критичные параметры (`TELEGRAM_TOKEN`, `OPENAI_API_KEY`, размеры чанков).

### Слой данных
- `pdm_bot/app/db.py`:
  - SQLite таблицы: `users`, `document_index`, `sync_state`, `indexing_jobs`, `messages`.
  - есть lock для потокобезопасного доступа.
  - хранит профиль пользователя (mode/tone/depth и пр.), историю сообщений, состояние синхронизации и очередь задач индексации.

### Индексация библиотеки
- `pdm_bot/app/indexing.py`:
  - перебирает документы в `docs` по расширениям,
  - вычисляет sha1 + mtime, чтобы индексировать только изменения,
  - удаляет старые векторы документа и апсертит новые чанки в Qdrant,
  - поддерживает фонового worker-а и очередь full reindex через SQLite job-таблицу.

### Парсинг документов
- `pdm_bot/app/documents.py`:
  - `txt/md` — чтение текста,
  - `docx` — через `python-docx`,
  - `pdf` — через `pypdf`, fallback на `pdftotext`,
  - очистка OCR-шума и разбиение на чанки с overlap.

### Retrieval и генерация
- `pdm_bot/app/retrieval.py`:
  - управляет Qdrant-коллекцией,
  - ищет top-k кандидатов по embedding,
  - смешивает vector score и keyword score в гибридный ранк,
  - ограничивает размер контекстного блока.
- `pdm_bot/app/llm.py`:
  - OpenAI embeddings + chat completion,
  - единая точка для вызовов LLM.
- `pdm_bot/app/prompts.py`:
  - формирует system prompt из профиля пользователя,
  - эвристически определяет тип запроса (definition/comparison/clinical/bibliography).

### Telegram UX
- `pdm_bot/app/telegram_handlers.py`:
  - команды: `/start`, `/help`, `/diagnose`, `/tone`, `/depth`, `/mode`, `/stats`, `/reindex`, `/index_status`, `/health`, `/collections`, `/jobs`, `/config`, `/debug`, `/sources`.
  - owner-only guard для критичных админ-команд.
  - сохраняет диалог в БД, тянет историю, строит контекст и отправляет ответ частями.

## Что хорошо
- Есть явное разделение на модули: config/db/indexing/retrieval/llm/handlers.
- Есть инкрементальная индексация и удаление “протухших” документов.
- Есть очередь задач индексации и статусные команды.
- Есть user-level настройки тона/режима/глубины и переключение показа источников.

## Риски и узкие места
1. **Сильная связка с внешними сервисами** (OpenAI + Qdrant): без них бот неработоспособен.
2. **SQLite + один lock**: для текущего масштаба ок, но при росте нагрузки может стать узким местом.
3. **Эвристический роутинг prompt’ов** в `prompts.py`: полезно, но хрупко к формулировкам.
4. **Ограниченная фильтрация домена**: `domain_scope` мапится по подстроке `corpus`, это может давать неточные отсечения.
5. **Отсутствие тестов в репозитории**: нет автоматической проверки ключевых сценариев.

## Веб-часть
- `index.html` + `app.js` + `styles.css` дают самодостаточный фронт для:
  - планирования консультаций,
  - визуального выбора мест в круге,
  - списка участников и состояния мест.
- Это отдельный UI-слой, не интегрированный напрямую с Telegram-ботом на уровне текущего кода.

## Вывод
По доступному коду это практичный MVP/прототип психодинамического ассистента с локальной библиотекой знаний и удобным Telegram-интерфейсом. Главные направления усиления: тестируемость, прозрачный onboarding (README/.env.example), и более строгая/масштабируемая логика retrieval-фильтрации.
